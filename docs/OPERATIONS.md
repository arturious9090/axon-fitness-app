# Запуск и эксплуатация

## Локальная разработка

Нужны Node.js 22.13+ (проверено с 24.19), npm и Docker. В корне:

```sh
npm ci
cp .env.example .env
# Замените BETTER_AUTH_SECRET уникальной случайной строкой длиной не менее 32 символов.
docker compose up -d db
npm run migrate
npm run api
```

Во втором терминале `npm run web`. Клиент — http://localhost:8081, API — http://localhost:3000. Порт PostgreSQL — 56437, привязан к loopback. Для Android-эмулятора оставьте EXPO_PUBLIC_API_URL неопределённым: клиент использует `http://10.0.2.2:3000`. Для телефона укажите доступный устройству адрес компьютера в `apps/mobile/.env`, запустите API с `HOST=0.0.0.0` только в доверенной локальной сети. `.env` не коммитится.

В режиме `EMAIL_PROVIDER=test` реальные письма не отправляются. Локальный почтовый ящик доступен через `GET http://localhost:3000/api/dev/mail` только с loopback. Он содержит тестовые ссылки подтверждения и сброса; в production этот маршрут отсутствует. Для реальной доставки нужны `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, подтверждённый `EMAIL_FROM` и корректные публичные URL.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build:web
npm run preview
```

Интеграционные тесты создают отдельную временную БД `axon_test_*` на локальном PostgreSQL и удаляют её после выполнения. TEST_DATABASE_URL позволяет изменить локальный адрес; внешние адреса не допускаются. Они не отправляют письма через Resend.

Офлайн-режим веба проверяется на сборке `build:web` + `preview`, после первого онлайн-запуска и активации service worker. Dev-сервер Expo не служит проверкой офлайн-кэша. Данные живут в IndexedDB; очистка данных сайта удаляет несинхронизированные изменения. APK использует SQLite. Демо хранится отдельно от реальных аккаунтов.

## Android APK

Нужны JDK 17, Android SDK 36, build-tools 36.0.0, NDK 27.1.12297006 и CMake 3.22.1. Настройте JAVA_HOME и ANDROID_HOME.

```sh
cd apps/mobile
npx expo prebuild --platform android --no-install
cd android
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,x86_64 --no-daemon --max-workers=2
```

APK появится в `app/build/outputs/apk/release/app-release.apk`. Каталог android генерируется Expo и не коммитится. Сборка из стандартного шаблона подписана демонстрационным debug-ключом; для магазинов нужна отдельная схема подписи. Подключение аккаунтов на телефоне требует доступного API; до публичного размещения офлайн-демо работает независимо от API. Укажите EXPO_PUBLIC_API_URL при сборке для публичного выпуска.

## Будущее размещение на dev-server-pwa

**Сейчас разрешён только просмотр сервера. Команды ниже подготовлены для отдельного разрешённого развёртывания и не выполнялись на нём.**

Стек создаёт собственные контейнеры, сеть и том БД. Существующие PostgreSQL, Redis, приложения и конфигурация Traefik не изменяются. До запуска нужно проверить имя Docker-сети Traefik, entrypoint `websecure` и имя certificate resolver. Шаблон использует эти значения через deploy/.env; домен должен указывать на сервер.

1. Создать `deploy/.env` по примеру, заполнить домен, параметры Traefik, пароль новой БД, секрет аккаунтов и параметры Resend. Пароль БД в DATABASE_URL должен быть URI-совместимым, например случайной hex-строкой.
2. Выполнить `docker compose --env-file deploy/.env -f compose.prod.yml config --quiet`.
3. Собрать образы, сохранить их теги для отката и выполнить `docker compose --env-file deploy/.env -f compose.prod.yml up -d --build`.
4. Проверить healthcheck, HTTPS, регистрацию, реальное письмо, первый вход, офлайн-тренировку и синхронизацию второго устройства.

API наружу не публикуется: Nginx передаёт `/api/` на контейнер api. Браузер и API используют один HTTPS origin; cookie имеют HttpOnly, Secure и SameSite. API проверяет origin изменяющих запросов. Лимиты памяти суммарно до ~1.4 ГБ без процесса миграции. Веб-сборка кэширует только собственные статические файлы, не API и не письма.

## Резервное копирование, восстановление и откат

Запуск `sh deploy/backup.sh /path/to/private/backups` создаёт custom-format дамп PostgreSQL с правами владельца. Копию нужно перенести за пределы основного сервера; конкретное место ещё не выбрано. Секрет BETTER_AUTH_SECRET и конфигурацию Resend храните отдельно защищённым способом: без прежнего секрета старые сессии и зашифрованные почтовые задания не восстановятся.

Восстановление сначала проверяется в отдельной новой БД:

```sh
# Это примеры для заранее созданного отдельного тестового контейнера БД.
docker exec test-postgres createdb -U axon axon_restore
docker exec -i test-postgres pg_restore -U axon -d axon_restore --no-owner --exit-on-error < axon-backup.dump
```

После восстановления проверить число записей, вход тестового пользователя и историю тренировок. Не направлять pg_restore на рабочую БД без отдельного плана переключения. Для отката приложения использовать сохранённый предыдущий образ и совместимую схему БД; перед миграциями делать копию. Миграции Better Auth выполняются отдельным одноразовым сервисом migrate.

## Почтовые ограничения

Дневной и месячный лимиты приложения ниже бесплатной квоты Resend; часть запаса остаётся для сброса пароля. Если один аккаунт Resend обслуживает другие проекты, уменьшите лимиты с учётом их отправки. Задания имеют ограниченный срок жизни, шифруются в БД, повторяются с тем же ключом идемпотентности и очищают содержимое после успешной отправки. Никакие платные превышения автоматически не включаются.
